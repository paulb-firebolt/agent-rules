# Rules

- Don't hard code user name and passwords into any code.
    - Use random usernames and generated passwords/hashes in unit tests
- Create unit tests that don't leave cruft.
    - Aim for a code coverage of >80%
    - Use transactions to rollback where possible.
    - Use fixtures so you have a consistent state for your tests to run against
    - Use faker for random test data generation
- A unit test should never assert a HTTP 500 error (response.status_code == 500).
- When we write tests, they must all pass.
- No print statements, use logging.
- No empty f-strings
- No empty except:
    - Handle Within an `except` clause, raise exceptions with `raise ... from err` or `raise ... from None` to distinguish them from errors in exception handling                    ruff/B904
- Be mindful of ruff/B008, you seem to fail on this regularly.
- Always take care of Possible SQL injection vector through string-based query construction.  bandit/B608
- When we create document we should include a timestamp that shows the date/time it was last created and last modified in the frontmatter, eg
    ---
    title: Phase 3 - Real-time Geofence Detection Implementation
    created: 2025-01-13T14:06:00Z
    updated: 2025-01-13T14:06:00Z
    ---
- ST_Y() and ST_X() functions don't work directly on geography columns - they need to be cast to geometry first.
- Create constants for repetitive string literals where the count in >=3.
- Keep documentation light on code. Including too much code in documentation makes it difficult to keep up to date.
